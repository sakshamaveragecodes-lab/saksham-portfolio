# Verification and release status

The actual execution results below concern this portfolio. Original project results are separately attributed in each case study.

## Executed locally

- Strict TypeScript, lint, production static export and lockfile installation were exercised.
- Seven algorithm/provenance tests passed, including 156 scoring comparisons generated by the original Python/sklearn JobMatcher and actual FORM geometry replay checks.
- Ten Playwright tests passed. They exercise the main recruiter journey, project filters, source links, actual demo updates, architecture selection, empty states, all 17 content routes, local assets, anchors, 404, sitemap, mobile navigation, keyboard skip navigation and reduced motion.
- Six representative pages were scanned with axe against WCAG A/AA rules, with no reported violations. Automated scans are not a full accessibility certification.
- Screenshots at 390, 768 and 1440 CSS pixels were captured. Representative desktop, tablet and mobile layouts were inspected. No document-level horizontal overflow was found on the six sampled routes.
- Software WebGL rendered the actual Three.js scene; its pause control worked and no application page errors were observed. This is not a physical GPU/device compatibility test.
- Guided pipelines, stored metric selectors, a recorded SourceLens case and actual CareerLens video playback were exercised. Initial HTML content was also checked with JavaScript disabled.
- Eighteen public GitHub/profile/source-snapshot links returned HTTP 200. See `qa/link-audit.json`.
- Dependency audits were run. Sharp and PostCSS were patched; lint/performance tooling was updated. The final audit result is recorded in `qa/dependency-audit.json`. Advisory checks reflect the registry database at execution time.

## Reproduce

```sh
npm ci
npm run lint
npm test
npm run build
npm run typecheck
npm run test:e2e
npm audit
```

For Lighthouse, start `npm start`, then use the installed Lighthouse CLI with a local Chromium executable. Production browser tests use `TEST_BASE_URL` and must be rerun after an actual public deployment. Tests intentionally verify the honest missing-resume state; they do not claim a resume download works without the actual file.
