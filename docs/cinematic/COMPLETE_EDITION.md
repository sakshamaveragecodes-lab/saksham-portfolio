## Rendering and lifecycle

One fixed shared stage is mounted in the App Router layout. The approved Home/SourceLens rich desktop path retains R3F physical materials and a procedural studio environment. Compact devices use its optimized native WebGL2 path. Added worlds use a small native WebGL2 instanced renderer and the same Three math classes, timeline state and original fluid shader. They do not instantiate another full Three renderer. Distinct object-space meshes, assemblies, cameras and deformation functions define the environments, rather than a common mesh recolored per route.

The additional material uses analytic lighting, reflection bands and Fresnel shading; it is not physically traced refraction. The fluid floor is an artistic shader, not fluid simulation. Hardware rendering resolution is capped; slow samples reduce it. Software Chromium is an intentionally constrained fallback and cannot establish physical-GPU performance. Chapter travel remains available while ambient motion is paused. Hidden/offscreen stages suspend rendering; resources are deleted on world changes/unmount. Context loss exposes a readable fallback and explicit retry. No WebGL, no JavaScript and reduced motion retain semantic content and all project tools.
